# LazyMins — Project Instructions

Qt6-based POS/percetakan management app (C++17, CMake). Organization: BlackCircle, default app name: LazyAdmins, executable: `LazyMins`.

## Dev Environment

- **Prereqs**: Qt 6.8+ (Widgets, Sql, Network, PrintSupport, SerialPort, Core5Compat, Test), CMake ≥3.23, C++17 compiler, Ninja (optional but used in CI).
- **Submodules required**: `escpos-qt` and `static_openssl_3.5`. Clone with `--recurse-submodules` or run `git submodule update --init --recursive` after checkout.
- **Qt on Windows (CI reference)**: Qt 6.8.3 win64_mingw, installed via `aqtinstall`. CMake needs `CMAKE_PREFIX_PATH` pointing to Qt root and `Qt6_DIR`.

## Build & Test

```bash
# Configure (Ninja generator, Release build)
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release

# Build
cmake --build build --config Release

# Run tests (one test binary: tstDatabase)
cd build && ctest

# Build test target only
cmake --build build --target build_tests
```

- Build produces `build/LazyMins.exe` (Windows) or `build/LazyMins` (Linux).
- Test binary is `tstDatabase` (from `tests/testDatabase.cpp`), links `core_utils` + `data_layer`.
- `build/` is in `.gitignore` — do not commit it.

## Conventions

- **Libraries** (static, layered): `core_utils` → `data_layer` → `model_components` → `ui_components` → `ui_dialogs`. Plus standalone: `printing_module`, `printer_setup_module`, `modul_laporan`.
- **Naming**: Indonesian identifiers throughout (e.g. `konsumen`, `akuntransaksi`, `kategoritransaksi`). Manager classes end in `Manager` (e.g. `Ordermanager`, `Productmanager` — note: some are lowercase 'm').
- **Macros**: `APP_ORGANIZATION` and `APP_NAME` are set via CMake `target_compile_definitions` from cache variables `APPLICATION_SET_ORGANIZATION_NAME` and `APPLICATION_SET_NAME`.
- **Database**: SQLite via Qt6::Sql. Schema initialization in `src/database/initializeschema.cpp`. App-level DB files: `lm.sqlite3` (tracked pattern in gitignore for `test_data/lm.sqlite3`), also `a.db`, `LAdmins.db` ignored.
- **Qt auto-features enabled**: `AUTOMOC`, `AUTORCC`, `AUTOUIC` — do not hand-write moc/rcc/uic output files.

## Pitfalls

- **Submodules not checked out**: build will fail with missing `escpos-qt` headers. Always init submodules after cloning or switching branches.
- **EscPosQt dependency**: `printing_module` and `printer_setup_module` link `EscPosQt` — it comes from the `escpos-qt` submodule. Without it, CMake `find_package` or target link fails.
- **CI is Windows-only**: GitHub Actions workflow (`.github/workflows/c-cpp.yml`) targets `windows-latest` with MinGW. Linux builds are not CI-tested.
- **Test data DB**: `test_data/lm.sqlite3` is gitignored — tests may expect a database at a path that doesn't exist in a fresh clone. Check `testDatabase.cpp` for setup.
- **Generated files**: `ui_*.h`, `moc_*.cpp`, `qrc_*.cpp` are auto-generated by CMake Qt integration. Do not edit them manually.
- **Branch name**: CI triggers on `qt6-main` branch (not `main`). Current branch is `qt6-main-fixation`.

## License Gate (offline installation validation)

Offline license validation via ECDSA P-256 signed tokens + HMAC-signed trial record. See `src/token/README.md` for full docs.

### Files

- `src/token/include/license_helper.h` — core API: `signToken`, `verifyTokenFile`, `verifyTokenString`, `scanTokenFolder`, plus embedded-key variants
- `src/token/src/license_helper.cpp` — implementation (OpenSSL)
- `src/token/include/embedded_pubkey.h` — embedded public key DER bytes (update when rotation needed)
- `src/token/include/trial_record.h` — trial record API header
- `src/token/src/trial_record.cpp` — HMAC-SHA256 trial record write/read
- `src/utils/licensegate.h` — high-level gate (`GateState`, `GateResult`, `initialize`, `showReminder`, `showBlockDialog`)
- `src/utils/licensegate.cpp` — Qt dialog implementation

### Integration point

In `src/main.cpp`: after `SetupWindow` flow and before `openLoginForm()`:

```cpp
licensegate::initialize();
auto res = licensegate::result();

if (res.state == licensegate::GateState::Reminder) {
    licensegate::showReminder(res.daysUsed, res.hardwareId, &mainWindow);
} else if (res.state == licensegate::GateState::Blocked) {
    if (!licensegate::showBlockDialog(res.hardwareId, &mainWindow)) {
        app.quit();
        return 0;
    }
} else if (res.state == licensegate::GateState::Error) {
    QMessageBox::warning(&mainWindow, "License", res.errorMessage, QMessageBox::Ok);
}
```

### Key pair workflow

1. Generate: `build/tools/keygen private.pem public.pem`
2. Never distribute `private.pem` — only use internally to sign tokens
3. Convert public key to DER for embed: `openssl pkey -pubin -in public.pem -outform DER -out public.der`
4. Read DER bytes: `xxd -p public.der`
5. Update `src/token/include/embedded_pubkey.h` array `PUBLIC_KEY_DER` with new bytes
6. Recompile — old tokens signed with previous key will no longer validate

For production: generate a dedicated production key pair, not the demo key in `src/token/build/`.

### Token file

- Filename: `.lm_token` (hidden file)
- Location: `QStandardPaths::AppDataLocation` + `/.lm_token`
  - Linux: `~/.local/share/BlackCircle/LazyMins/.lm_token`
  - Windows: `%APPDATA%\BlackCircle\LazyMins\.lm_token`
- Create with `sign_demo`: `./tools/sign_demo private.pem output.lm_token [hwid]`
- Optional HWID binding: pass HWID as 3rd arg to lock token to a machine

### Trial record

- Filename: `.lm_trial` (hidden file)
- Location: same AppData path as token, `/.lm_trial`
- HMAC-SHA256 signed with embedded secret
- Created automatically on first run of new version if missing
- Deletion = fresh install signal (accepted behavior)
- Tamper-evident: modified content detected via HMAC mismatch → `GateState::Error`

### Trial timeline

- Day 0–59: Trial (no dialog)
- Day 60–89: Reminder (non-blocking info dialog, app still usable)
- Day 90+: Blocked (modal dialog, app exits if no valid token loaded)

### Token verification in app

- App looks for `.lm_token` in AppData path at startup
- Verifies signature against embedded public key
- If valid: `GateState::Licensed`, app runs normally
- If no token or invalid: applies trial timeline above

### Developer-only token creator

A separate `LazyMins-TokenCreator` app is planned (not yet built). For now, use `sign_demo` CLI tool to create tokens.
